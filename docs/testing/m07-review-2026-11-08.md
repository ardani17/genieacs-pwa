## Spec

1. Password replacement strict dan keep memerlukan secret yang ada.
2. Key hilang/salah atau GCM rusak menghentikan perubahan tanpa fallback env.
3. Controller dapat memicu bootstrap sebelum kunjungan admin pertama.
4. Deployment benar-benar memasok kandidat bootstrap dan secret file.
5. Bootstrap/reset tanpa password tidak menghapus atau membuat profil invalid.
6. Reset mempertahankan installationId.
7. Exit19/PAP/CHAP menjeda retry; revisi/reconnect membuka pause.
8. Seluruh process group dihentikan sebelum generasi baru dimulai.
9. Cleanup hanya menyentuh rute dengan ownership yang cocok; jurnal gagal tetap
   ada.
10. Shutdown tidak memulai koneksi dari fetch yang terlambat.
11. Host PPP tidak didukung dilaporkan tanpa redial loop.
12. Badge dashboard memakai status VPN berizin yang aktual.
13. Feedback live tidak menutupi CAS error dan berubah saat retry berhasil.
14. Logging health mencakup file UI/web/controller, Vector, sink,
    dropped/buffer, waktu gangguan/keberhasilan, dan warning kapasitas80%/90%

## Lab L2TP nyata

Endpoint khusus yang diberikan pengguna diuji melalui client image produksi,
NET_ADMIN dan /dev/ppp, tanpa privileged atau Docker socket. Modul host
ppp_generic/ppp_async dimuat pada Docker Desktop WSL. Kernel ini tidak memiliki
modul L2TP PPP, tetapi transport userspace xl2tpd berhasil membentuk tunnel.

- Connected pada ppp0; desiredRevision sama dengan appliedRevision.
- Stabil lebih dari60detik mereset attempt menjadi0.
- Reconnect200; permintaan duplikat409; koneksi kembali connected.
- Satu proses xl2tpd dan satu pppd; tidak ada default route melalui PPP.
- Revisi2 memasang CIDR TEST-NET pertama. Revisi3 menghapus rute lama dan
  memasang CIDR TEST-NET berikutnya; dua rute owned mencakup rute endpoint.
- Client lab dan source fixture dihentikan setelah verifikasi.

Kredensial dan detail status lab tetap pada secrets/ dan artifacts/ lokal yang
diabaikan Git serta dikecualikan dari Docker build context. Lab memakai CIDR
TEST-NET, bukan perubahan konfigurasi perangkat produksi. Runbook deployment
menjelaskan pemasangan secret, route ingress dan migrasi path log lama.
